## 1. מנות — רשות האוכלוסין

`src/tik/manot.js` · `src/tik/cp1255.js` · ממשק ב-`#manot`

> ⚠️ **`MANOT.calibrated = false`** — רוחבי השדות **זמניים**. אין לשדר לפני
> כיול מול קובץ דוגמה אמיתי. ראה `NEEDS.md`.

### מבנה הקובץ

שורה באורך **704 תווים קבוע** לכל רשומה, קידוד Windows-1255, ואחריהן שורת
כותרת תחתונה קבועה — מופרדות ב-CRLF, עם CRLF גם בסוף.

```
'500' + מספר לשכה בן 9 ספרות + קוד פעולה בן 6 ספרות + [שדות ברוחב קבוע] + '000'
50021609556809990001
```

שם הקובץ: `oz_siud_manot_216095568_NN.txt`

⚠️ **`MANOT.corpId` הוא `216095568` — מספר הלשכה, לא ח.פ.** ח.פ החברה הוא
`513996488` (`placementCertificate.js`). הקוד קורא לשדה `corpId`, ומקומות
אחרים מדפיסים `216095568` בעמדות בצורת ח.פ. **דורש אישור לקוח לפני שידור.**

### קודי פעולה

| פעולה | קוד |
|---|---|
| מעבר בין מעסיקים | `090202` |
| מחליף מלשכה אחרת | `090205` |
| מחליף מלשכה אחרת · 51-63 חודש | `090205` |
| הברקה · הזמנת עובד מחו״ל | `090104` |

שתי וריאציות "מחליף" חולקות קוד זהה ונבדלות רק בנוסח מכתב הלוואי.
"הברקה" מוסיפה שדות כתובת מוצא (`foreignAddress: true`).

### רצף השדות

מוגדר בפונקציה `segmentsFor(action, d)` — **19 מקטעים**, ו-**22** עבור הברקה
(`foreignAddress`). שלושת הראשונים הם הכותרת (`prefix`/`corp`/`action`);
השאר הם שדות הנתונים:

| שדה | רוחב |
|---|---|
| ארץ | 3 |
| דרכון | 15 |
| שם משפחה / פרטי / האב באנגלית | 20 כל אחד |
| שם משפחה בעברית | 22 |
| שם פרטי בעברית | 20 |
| ספרת מין + תאריך לידה YYYYMMDD | 9 |
| בלוק היתר | 24 |
| `'1'` + ת״ז מעסיק | 10 |
| שם משפחה / פרטי של המעסיק | 18 כל אחד |
| ספרת מין + סמל יישוב | 9 |
| יישוב | 20 |
| רחוב | 30 |
| טלפון | 12 |

מין ממופה לספרה מובילה: `1` / `2` / `0`.

**כל המבנה קיים כדי שנעילת הפורמט תהיה עריכה במקום אחד.** (ההערה בקוד
מכנה אותו "טבלת SEGMENTS", אבל אין סמל כזה — רק `segmentsFor()`.)

### קודי ארצות שהוזנו

הודו 110 · פיליפינים 131 · אוזבקיסטן 315 · סרי לנקה 112

### `cp1255.js` — המקודד

מקודד Windows-1255 שנכתב ידנית:

- ASCII עובר כמו שהוא
- `א`..`ת` → `0xE0 + היסט`
- מפת `EXTRA` ל-₪, גרש, גרשיים, מקפים, מרכאות
- **תו לא מוכר → רווח** — כדי שגליף חורג לעולם לא יזיז את הרשת הקבועה

## 2. דוח רבעוני למשרד הפנים (301)

`src/tik/interiorReport.js`

### הדוקטרינה: להזריק, לא לבנות מחדש

ה-`.xlsx` הרשמי של המשרד מצורף כנכס קבוע
(`src/tik/assets/interior-quarterly-template.xlsx`, 390KB). הקוד פותח את ה-zip,
משכתב את `xl/worksheets/sheet2.xml` כמחרוזת, ומזריק ערכים ל**שורות הריקות
המעוצבות מראש 9-508** (`ROWS_AVAILABLE = 500`), תוך שימוש חוזר בעיצוב של כל תא.

| C | שם משפחה — משפחה | |

| F | רחוב | |

| H | שם משפחה — עובד/ת | |

⚠️ **שם העובד/ת מועדף מהשדה האנגלי** —
`c.worker?.nameEn || f.nameEn || v.workerName` — בעוד שם המשפחה נלקח מהעברי.

אחרת המסגרות וההצללה נשברות. זו כל הנקודה של השיטה.

⚠️ נכללים **רק ביקורים עם תאריך ביצוע**. הסינון ב-`ReportPage.jsx`.

### טבלת ה-styles — קריטית ולא ניתנת לגילוי

| עמודות | style |
|---|---|
| `A` | `14` |
| `B` / `H` / `M` | `61` (פתיחת קבוצה) |
| `C`-`F` / `I`-`K` / `O`-`Q` | `60` |
| `G` / `L` / `R` | `62` (סגירת קבוצה) |
| `N` (סטטוס) | `63` |

הסגנונות 60-63 **נוספו לתבנית** כווריאציות תואמות-מסגרת הנושאות fill 5 —
ההצללה התכולה `#E0E9F8` שדוחות אמיתיים משתמשים בה.

### 🔑 תאריכים חייבים להיכתב כטקסט

```xml
<c r="..." s="..." t="inlineStr"><is><t xml:space="preserve">31/03/2026</t></is></c>
```

התאים בפורמט "General". מספר סידורי גולמי יוצג כמספר עירום — זה היה הבאג המקורי.

### מיפויים

| סוג ביקור | טקסט בטופס |
|---|---|
| השמה | `טרום השמה` |
| 30 יום | `אחרי` |
| שוטף | `שוטף` |

`PLACEMENT` ממפה **6 מפתחות ל-3 פלטים**:

| קלט (ניסוח המשרד) | פלט (הטופס) |
|---|---|
| `השמה מהארץ` | `השמה מהארץ` |
| `השמה מחו״ל` | `השמה מחול` |
| `השמה מחול` | `השמה מחול` |
| `העברה מלשכה אחרת` | `השמה מהארץ` |
| `רישום לתאגיד` | `רישום בלבד` |
| `רישום בלבד` | `רישום בלבד` |

⚠️ הפלט `השמה מחול` הוא **ללא גרשיים** — כך הטופס מצפה.
נפילה לאחור: `placementFromIsrael === 'לא' ? 'השמה מחול' : 'השמה מהארץ'`.

`DEFAULT_ROLE = 'ע.סוציאלי'`. תאי כותרת: C4 סוכנות, C5 שנה, C6 רבעון.

`splitName()` כאן: **שם משפחה ראשון**.

### מנגנון השכתוב

- התאמת `<row r="N"(attrs)>…</row>` עם דגל `s`, ו**פליטה מחדש של מאפייני
  הפתיחה המקוריים** של השורה (גובה, spans)
- נפילה לאחור: `spans="1:21" x14ac:dyDescent="0.2"`
- שורה חסרה נוספת לפני `</sheetData>`
- `setHeaderCell()` קורא מחדש את ה-`s="…"` של התא עצמו כדי לשמר את עיצוב הכותרת

גיליון הצהרת המנהלים נשאר ללא נגיעה.

אין חתימה דיגיטלית מוטבעת — המשרד מוריד וחותם ידנית.

### אמצעי תשלום

מזומן 1 · המחאה 2 · כרטיס אשראי 3 · העברה בנקאית 4

### אלגוריתם המספור

1. קרא את המספר הגבוה ביותר הקיים לסוג הזה
2. +1
3. הוסף
4. בשגיאת `duplicate|unique` — **קרא מחדש וטפס**, עד **25 ניסיונות**

⚠️ הלולאה חסרת-פערים **רק אם קיים אינדקס ייחודי** — והוא אינו מוגדר
ב-`schema.sql`. `docType` ו-`number` אינן עמודות אלא שדות בתוך `data` jsonb,
ולכן נדרש **אינדקס ביטוי חלקי**. ה-DDL: `docs/OPEN-ISSUES.md` §8.

### מע״מ

`VAT_RATE = 0.17`. `vatBreakdown()` גוזר את הנטו **אחורה מברוטו כולל מע״מ**,
כי כך מצוטט המחיר ללקוח.

### תנאי מקדים — מפתחות ההגדרות

`companyDetails()` קורא משורת ה-`config`. בלי **ח.פ** ההנפקה זורקת שגיאה:

`companyTaxId` · `companyName` · `companyAddress` · `companyPhone` ·
`companyEmail` · `companyBankName` · `companyBankNumber` · `companyBankBranch` ·
`companyBankAccount` · `workerFeeTotal`

רק `companyTaxId` הוא חובה קשיחה — היעדרו זורק.

בנוסף נדרש `COMPUTERISED_STAMP` — נוסח "מסמך ממוחשב" שהתקנות מחייבות.

⚠️ זיכוי של זיכוי זורק שגיאה.

### כלל ההקפאה

**אין נתיב UPDATE בקוד.** `creditDocument()` הוא התיקון היחיד, והוא כותב אירוע
`credited` ביומן במקום לשנות את המקור.

### יומן ביקורת

`kind: 'taxdoc_event'` · אירועים: `issued` / `printed` / `emailed` / `credited`

## 7. קטלוג הדוחות

`src/tik/reports.js` · `src/tik/ReportPage.jsx`

**74 דוחות כדאטה הצהרתית** — 44 רשומות מפורשות במערך `R` + **30 שנוצרות
במפעל `statReport()`** ונדחפות אליו (`R.push(...STATS)`). כל דוח הוא:

```js
{ no, group, label, desc, params, columns, run }
```

`ReportPage` מריץ כל אחד מהם דרך אותה זרימה פרמטרים → תוצאות. **הוספת דוח היא
הוספת רשומה בטבלה.**

### שמונה קבוצות (`REPORT_GROUPS`)

| id | כותרת | היקף |
|---|---|---|
| `workers` | דוחות עובדים | כלליים |
| `clients` | דוחות לקוחות | כלליים |
| `visits` | דוחות ביקורים/הערות | כלליים |
| `quarterly` | דוחות רבעוניים | כלליים |
| `invoices` | דוחות חשבוניות | כלליים — פותחים את `#invoices`, לא עמוד פרמטרים |
| `personal` | דוחות אישיים | לפי רכז/ת |
| `office` | דוחות המשרד | כלליים |
| `stats` | **דוחות סטטיסטיים** | ריכוזים — כל 30 דוחות ה-`statReport` |

### מפעל הדוחות הסטטיסטיים

`statReport({ no, label, population, groupBy, groupLabel, chronological, desc })`
בונה דוח ריכוז מ-`POPULATIONS` (אוסף האוכלוסיות), `tally()` (הספירה) ו-
`STAT_COLUMNS(groupLabel)`. 30 קריאות למפעל הזה מייצרות את כל הקבוצה.

⚠️ חלק מ-48 הרשומות המוצהרות הן **קצרמרים לא ממומשים** הנושאים מחרוזת `soon:`
שמסבירה למה. הדגל `soon` הוא המנגנון; מי מהדוחות חלול נקבע רק בקוד.

⚠️ 74 הדוחות עצמם אינם מרושמים כאן. מי ששואל "האם קיים דוח ל-X?" חייב לקרוא
את `reports.js`.

### מנגנונים

- `COL` — צורות עמודה משותפות
- `dateReport()` — קומבינטור לדוחות מבוססי תאריך
- `byRakaz()` — סינון לפי רכז/ת
- `soon` — דגל לדוח ששמור אך טרם מחושב
- `runReport()` — גוזר אוטומטית רבעון → טווח תאריכים
- `keyOf()` — מפתח מסלול עם קידומת `p`/`o`/`s`/`r`, מזין את `#report/<key>`
