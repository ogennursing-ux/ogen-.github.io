# חוקים עסקיים

כללים שנקבעו מול הלקוח או נגזרים מהחוק. אף אחד מהם לא ניתן לניחוש מהקוד בלי
ההקשר, ורובם נלמדו מנזק אמיתי.

---

## 1. מקצב ביקורי העו״ס

`src/tik/socialWorker.js`

כל השמה חייבת סדרת ביקורים קבועה, נספרת מתחילת ההשמה:

| ביקור | מתי |
|---|---|
| **ביקור השמה** | בתאריך תחילת ההשמה |
| **ביקור 30 יום** | תחילה + 30 יום |
| **ביקור שוטף** | כל 6 חודשים (`m = 6; m += 6`) |

הסדרה נוצרת עד אופק של **120 חודשים**. האופק נדיב בכוונה — השמות רצות 5-6 שנים,
ותקרה קצרה מפילה עובדים ותיקים מהדוח הסטטוטורי בשקט.

מוצגים רק ביקורים שמועדם בתוך היום + 6 חודשים.

### נפילה לאחור בתאריך ההתחלה

```js
start = startDate || placementStartDate
```

עובד שרק אחד מהשניים מולא אצלו היה מייצר אפס ביקורים ונעלם מהדוח.

### קבועים

| קבוע | ערך | משמעות |
|---|---|---|
| `GRACE_DAYS` | `0` | ביקור באיחור כבר למחרת מועדו |
| `soon` | ≤ 30 יום | מסומן כמתקרב |
| `REPORT_DUE_DAY` | `10` | הדוח הרבעוני מוגש עד ה-10 בחודש שאחרי סוף הרבעון |

### ערוצי ביקור

`physical` (ברירת מחדל) · `phone` · `digital`

הערוץ נרשם לכל ביקור **כי משרד הפנים דורש דיווח נפרד לכל ערוץ** — דוחות
301, 301.1, 301.2.

### דלייה בפורטל

`src/lib/visitWorklist.js` מסווג ל: `overdue` / `week` / `month` / `quarter` / `later`.

## 2. שלוש פעימות התשלום של העובד/ת

`src/tik/registry.js`

העובד/ת משלם/ת לסוכנות בשלוש פעימות, נספרות **מיום הנחיתה בישראל**:

| פעימה | מתי |
|---|---|
| 1 | בהגעה (0 חודשים) |
| 2 | + **26** חודשים |
| 3 | + **38** חודשים |

### התאריכים לא נשמרים

רק בוליאני `fields.workerPaymentsDone[key]`. המועדים נגזרים בכל פעם מחדש.

### 🔑 הכלל שקל לפספס

הסוכנות רשאית לגבות **רק פעימה שנופלת ביום שבו העובד/ת כבר הצטרפ/ה לתאגיד
שלנו** (`startDate`).

עובד/ת שעבר/ה אלינו בחודש 28 חייב/ת **רק את פעימה 3**. לעולם לא 1 או 2.

### תצוגה

שלוש הפעימות מתקפלות לתא יחיד `wpayNext` בטבלת החידושים, בארבעה מצבים:
`none` / `allPaid` / הפעימה הבאה / באיחור.

התרעה חודש מראש (`WPAY_ALERT_MONTHS = 1`), וסימון `thisWeek` בשבעת הימים
האחרונים.

## 3. חמישה סוגי חידוש — וחלונות התרעה א-סימטריים

`RENEWAL_TYPES` ב-`src/tik/registry.js`:

| סוג | שדה | התרעה | ידני? |
|---|---|---|---|
| תוקף ויזה / אשרה | `visaExpiry` | **2 חודשים** | |
| תוקף דרכון | `passportExpiry` | **2 שנים** | |
| תוקף היתר העסקה | `permitExpiry` | **3 חודשים** | |
| תוקף ביטוח רפואי | `insuranceExpiry` | **10 ימים** | ✔ |
| חידוש דמי תאגיד | `companyFeeRenewalDate` | **10 ימים** | ✔ |

**למה שנתיים לדרכון**: החלטת לקוח מפורשת. המערכת הישנה שלהם התריעה 18 חודשים
מראש; הלקוח בחר 24. תועד ב-`GAPS.md` כהערת אגב בלבד.

**`manual: true`** = לא נאסף בסריקת מסמך, המשרד מקליד ידנית.

### מבנה הדוח

שורה אחת **לכל תיק**, כל סוג חידוש הוא עמודה — **לא** שורה לכל מסמך. כל תא
נצבע עצמאית, והשורות ממוינות לפי המועד הקרוב ביותר.

### `activePlacements()`

השמה נחשבת פעילה אם: יש עובד/ת **וגם** יש משפחה **וגם לא** מתקיים
`workerStatus ∈ ['לא מועסק', 'עזב/ה את הארץ']` או `caseStatus === 'סגור'`
או `closedDate` מלא.

⚠️ הרשימה הזו אינה תואמת את אוצר 28 הסטטוסים. ראה `docs/OPEN-ISSUES.md` §9.

## 4. מחזור חיי תיק

`src/tik/casesBoard.js`

```
missing → ready → sent → partial → signed
```

מעבר ל-`ready` מותנה ב-**שבעה** שדות `ESSENTIALS`:

1. שם מעסיק
2. ת״ז מעסיק
3. טלפון מעסיק
4. שם העובד/ת
5. דרכון העובד/ת
6. שכר חודשי
7. תאריך תחילת העסקה

ובנוסף שני `DOC_ESSENTIALS` — סריקת דרכון וסריקת ת״ז מטופל — שהם **מומלצים
אך אינם חוסמים**. ההפרדה בין "חוסם חוזה" ל"רצוי" היא החלטת לקוח.

## 5. בדיקת תקינות נתונים

`src/tik/dataQuality.js` — **מבוסס חוקים, לא AI.** ההערה בקובץ מסבירה למה:
כדי שדגל יהיה תמיד אמין.

| בדיקה | פירוט |
|---|---|
| ת״ז **מעסיק** לא תקינה | ספרת ביקורת ישראלית. חומרה: `warning` |
| דרכון כפול | ≥4 תווים, אותיות נשמרות (דרכונים אלפאנומריים) |
| סדר תאריכי השמה | התחלה אחרי סיום |
| גיל בלתי אפשרי | >100, <16, או תאריך לידה בעתיד |
| שדות חיוניים חסרים | **רק על השמות פעילות** |

### אלגוריתם ספרת הביקורת

הכפלת ספרות לסירוגין, חיסור 9 כשהתוצאה >9, וסכום מתחלק ב-10.

הבדיקה רצה על **ת״ז המעסיק** (`fam.idNumber`), לא על העובד/ת.
